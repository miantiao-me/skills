# 中文写作与审校参考指南

本指南汇集现代技术写作规范、清晰优雅的句法规则、24 种去 AI 味反模式清单与严苛审校工作流，指导简体中文的起草与润色。

---

## 1. 清晰与优雅：句法与结构

清晰的中文依赖清晰的动作与明确的主体。文字的优雅不靠辞藻堆砌，而源自逻辑流动的自然呼吸。

### 1.1 动作与角色（Actions & Characters）

- **以纯粹动词驱动**：坚决消除「动词名词化（Nominalization）」。在中文里，动词名词化通常表现为「进行 + 抽象名词」、「做出 + 名词」或「充当……的载体」。
  - ❌ 错误：针对这套系统，我们进行了稳定性的全面分析，并做出了相应的优化调整。
  - ✅ 正确：我们全面分析了系统的稳定性，并优化了架构。
  - ❌ 错误：该协议充当了客户端与服务端连接的桥梁。
  - ✅ 正确：该协议连接了客户端与服务端。
- **角色清晰，主动优先**：让动作发起者占据主语位置，避免无主句滥用与被动句泛滥。
  - ❌ 错误：随着新特性的发布，开发者的调试效率被大幅提升了。
  - ✅ 正确：新特性显著提升了开发者的调试效率。
- **消除系动词回避**：不用「作为……」、「扮演着……角色」回避直接陈述。
  - ❌ 错误：Rust 作为一种内存安全的语言，为高性能服务提供了坚实基础。
  - ✅ 正确：Rust 兼具内存安全与高性能，适合构建底层服务。

### 1.2 信息流与凝聚力（Cohesion & Emphasis）

- **旧到新（Old-to-New）原则**：句首承接上文已引入的已知概念（旧信息），句尾展开未知推论或重点（新信息）。
  - 如果上一句谈论「Cloudflare Workers 的冷启动时间」，下一句开头就应以「这种冷启动表现……」或「这个时间窗口……」承接，而不是突然跳跃到全新的主语。
- **尾重音原则（Stress Position）**：读者对句尾的记忆最深。将整句话最核心的结论、最重磅的数据或最具启发性的概念留在句末，而不是埋在从句中间。
- **保持段落焦点**：一段只讲一个核心意图。一旦转向另一个话题，立即拆分段落。

### 1.3 可扫读性与排版规范（Scannable Formatting）

- **小标题自明**：标题长度控制在 15 字以内，点明核心信息，除问号外不带标点，禁止标题党。
- **短段落**：每段建议 2–5 行，避免密集大文本块。
- **列表分工明确**：
  - **无序列表**：用于平级特征、功能、候选方案或同类清单；
  - **有序列表**：严格仅用于有先后时序、操作步骤或排名层级的场景。
- **中英文排版（盘古之白）**：
  - 中文与英文字母、半角数字之间保留一个半角空格（如「在 Node.js 22 中」、「测试了 3 组数据」）；
  - 中文标点使用全角字符（，。！？：；“”‘’）；中文标点与英文/数字之间不加空格；
  - 专业名词保留官方标准大小写（如 GitHub、macOS、Cloudflare、Next.js、SQLite，严禁随意小写）。

## 2. 去 AI 味与人类声音

大模型生成的文本往往带有「无菌」的平庸感与虚假的宏大感。消除机器味，关键在于拆除 AI 的思维钢印，恢复真实交流的细节与节奏。

### 2.1 常见 24 种 AI 写作反模式

#### 维度一：内容模式
1. **过度宏大叙事与历史意义**：动辄使用「标志着……新时代」、「揭开了……的新篇章」、「具有里程碑意义」、「为……奠定坚实基础」。直接陈述事件本身。
2. **过度强调曝光与虚假知名度**：使用「在业内引起广泛热议」、「备受瞩目」、「一经推出便火爆全网」，缺乏实测数据支撑。
3. **肤浅分析式收尾**：在段末机械追加「反映了……趋势」、「彰显了……的决心」。删去这些空话，让事实自己发声。
4. **宣传式浮夸措辞**：使用「令人叹为观止」、「无与伦比」、「革命性」、「令人惊叹」等空洞赞词。改用技术参数与具体场景。
5. **模糊归因与空气信源**：使用「专家认为」、「业内普遍指出」、「据分析人士称」。给出具体人名、论文、官方链接，或直接亮明论点。
6. **提纲式“挑战与展望”尾巴**：结尾强行拼凑「面临的挑战」与「未来的广阔前景」。无具体洞见时直接在主要事实处收尾。

#### 维度二：语言与语法模式
7. **高频 AI 词汇滥用**：如「此外」、「深入探讨」、「至关重要」、「格局」、「织锦（Tapestry）」、「充满活力」。
8. **系动词回避**：用「充当……」、「作为……的存在」代替清晰的「是」。
9. **虚假否定式排比**：套用「不仅是……，更是……」、「这不仅仅是一次升级，而是一场思维的革命」。改用单句直接陈述。
10. **机械三段式列举**：习惯性罗列三个形容词（如「快速、安全且可扩展」）。改用两项或具体展开单项。
11. **同义词刻意循环**：同段内为了“避免重复”，轮换使用「挑战」、「困难」、「障碍」、「瓶颈」，显得生硬造作。使用最精准的词即可。
12. **虚假范围界定**：使用「从 X 到 Y 再到 Z，全方位涵盖」假装全面。

#### 维度三：风格与排版模式
13. **破折号滥用**：高频使用「——」插入补充说明。改用逗号或拆成短句。
14. **粗体泛滥**：频繁加粗导致页面斑驳、重点尽失。仅在关键专有名词或核心结论处加粗。
15. **列表依赖症**：原本两句话能讲清的事，强行拆成带小标题的垂直列表。
16. **英文式标题大小写**：中文标题严禁模仿英文 Title Case，保持自然中文语序。
17. **表情符号泛滥**：在标题与列表项堆砌 🚀、💡、🔥、✨。除非明确要求，一律不加。
18. **引号混用**：统一使用「」或“”全角引号，不夹杂半角英文引号。

#### 维度四：交流与填充模式
19. **协作对话残留**：留下「好的，这是为您总结的……」、「希望这篇文档对您有所帮助！」。
20. **知识截止期免责声明**：无意义附带「截至我所知的信息……」。
21. **谄媚与卑躬语气**：开头写「这是一个极具深度的好问题」、「非常精彩的见解」。直接切入正题。
22. **碎屑填充短语**：在句首句中散落「值得注意的是」、「不难发现」、「显而易见的是」、「不可否认」。
23. **过度防御与和稀泥**：任何观点都强加一段平庸折中，导致文章毫无立场与锋芒。
24. **机械积极收尾**：结尾强行升华至「让我们拭目以待更美好的明天」。

### 2.2 高频警示词平替表

| 警示词汇 | 问题所在 | 改写建议 |
| :--- | :--- | :--- |
| **此外 / 除此之外** | 偷懒的逻辑连接词，句式机械 | 直接删除另起一句，或用自然语义承接 |
| **至关重要 / 举足轻重** | 夸大重要性，空洞无物 | 改为「重要」、「关键」，或具体说明不这么做的后果 |
| **深入探讨 / 深入剖析** | 假装深刻的填充词 | 改为「分析」、「讨论」、「梳理」 |
| **不断演变的格局** | 典型的机器翻译废话 | 改为「行业变化」、「当前趋势」或直接点明具体变化 |
| **作为……的证明** | 系动词回避与虚假象征 | 直接陈述具体事实与数据 |
| **不仅……更是……** | 刻意煽情排比 | 改用直截了当的肯定句 |
| **显而易见 / 众所周知** | 读者质疑源头，居高临下 | 直接给出事实或推导过程 |
| **提供强大的赋能** | 互联网黑话与大而无当 | 说明具体提供了什么能力或工具 |

### 2.3 注入真实的人类声音

消除 AI 痕迹不是让文字变成「无菌」的冷漠公文。人类写作的核心特征是有观点、有偏见、有节奏、有具体的感官细节：

- **长短句交错**：短句交代事实，制造顿挫；长句展开逻辑，提供纵深。如果连续三句话字数几乎相同，必须打断其中一句。
- **具体细节胜过抽象概括**：
  - 抽象 AI 腔：「该模型在复杂推理方面展现出极佳的性能与稳定性。」
  - 真实人类声音：「实测跑了 50 次长链路数学证明，除了第 12 次超时，其余均在 8 秒内输出了正确答案。」
- **允许真实的个人反应与态度**：科技写作可以有态度。适度使用「我」、「我们」，承认复杂性与犹豫（如「这很巧妙，但我很怀疑它能否通过生产环境的并发检验」）。
- **信任读者**：不反复解释隐喻，不频繁软化观点，直接把判断交给读者。

## 3. 严苛的审校工作流（Copyediting Discipline）

把大模型当做审校员，而不是代笔。作者负责产生灵魂、观点与原始材料，审校员负责执行无情的工程级质量挑刺。

### 3.1 两大铁律

1. **铁律一：绝不直接照搬 LLM 建议的修饰金句**
   大模型擅长输出类似商业杂志大标题的华丽修辞。这些句子单独读来悦耳，堆在一起却会抽干文字的独特性，变成毫无生气的人造芝士（Velveeta）。面对模型给出的精巧修辞，只提取其逻辑指出的问题，用自己的语言重写，坚决不照抄其原话。
2. **铁律二：绝对拒绝夸奖与谄媚（Avoid Encouragement）**
   初稿中几乎一定存在逻辑断裂、多余段落和表达冗余。大模型天生倾向于迎合用户（「写得太棒了！」）。审校任务必须预设零容忍挑刺姿态，要求模型把 80% 的精力花在找茬、裁剪和指出逻辑断层上，禁止任何廉价赞美。

### 3.2 四步机械扫描法

对文稿执行分层、分阶段的单向排查：

```text
文稿初稿
  │
  ├─► Pass 1：结构与剪裁（是否有 15%~30% 的段落可以删除或移位？）
  │
  ├─► Pass 2：动作与角色（动词名词化清查、主谓关系归位）
  │
  ├─► Pass 3：锯末清扫（剔除“此外/其实/非常/显然”等碎屑填充词）
  │
  └─► Pass 4：节奏与呼吸感（打破等长句、拆解双重否定与假排比）
```

- **第一遍（结构裁撤）**：跳出局部语句，审视段落顺序。哪些段落删掉后完全不影响核心价值？哪两个段落调换位置逻辑更顺？果断砍掉冗余部分（通常能精简 15%–30%）。
- **第二遍（动作还原）**：检索每一个「进行」、「做出」、「作为」，找到其后跟着的抽象名词，还原为真正动词。检查是否存在被动语态，改为明确动作人。
- **第三遍（锯末清扫）**：像清理木工工作台上的锯末一样，清扫文中的口癖与润滑词：删掉「其实」、「实际上」、「非常」、「不得不提」、「毫无疑问」。
- **第四遍（节奏重塑）**：大声默读，感受呼吸。连续出现短句时用连贯逻辑合并；遇到三行不断的长句时果断在逗号处切断成两句。

## 4. 典型文体实战范式

### 4.1 周刊与资讯条目（AIGC Weekly 风格）

**核心结构**：标题 + 2–4 句精要摘要（链接自然嵌入主干词，不独立挂链接）。

- **起手原则**：第一句直接交代发生的核心事件与主体，禁止寒暄（“本周发生了一件大事……”）。
- **主体内容**：
  - 工具/项目：是什么 → 解决什么痛点 → 核心亮点与部署门槛。
  - 模型发布：核心架构/参数 → 关键跑分或实测优势 → 成本/开源协议变化。
  - 行业动态：事件事实 → 行业实质影响（不夸大其词）。
- **范例**：
  - ❌ 错误：
    > 令人瞩目的新工具上线！在当今不断发展的 AI 格局中，某团队发布了一款极其强大的开源本地搜索引擎。它作为新一代搜索技术的代表，不仅速度飞快，更是能深度理解语义。[点击此处查看原文]
  - ✅ 正确：
    > [takumi-pdf](https://github.com/example/takumi-pdf) 是一个轻量级 PDF 导出库，支持完全在浏览器端通过 WebAssembly 运行。相比传统的 Canvas 截图拼接方案，它导出的文本可直接复制，样式还原度更高，单页生成耗时在 200ms 以内。

### 4.2 极客随笔与微文（memo.miantiao.me 风格）

**核心基调**：短小精悍、老派 Hacker 精神、实测数据与边界先行、不端不装、适度幽默。

- **实测说话**：用具体的数字与环境说话（“实测冷启动 12 秒”、“每月 4000 分钟才划算”），不谈空洞概念。
- **抠字眼与边界感**：分清「能确认的日志」与「推测的结论」，不夸大危险或功能（如“能确认的是 DNS 查询，不等于录到了通话内容”）。
- **自然的人性化切入**：允许真实的折腾记录与自嘲（“纯本地运行，你写给初恋的情书不担心泄露了”、“又被装到了”）。
- **范例**：
  - ❌ 错误：
    > 近期我对 GitHub Actions 的计费机制进行了深入探究，发现其在某些场景下存在成本过高的问题。通过引入无服务器容器技术，我们成功构建了一套创新的运行架构，为开发者降本增效奠定了坚实基础。
  - ✅ 正确：
    > 试着把 GitHub Actions Runner 塞进了 Cloudflare Containers。任务启动冷启动约 11 秒，短任务确实便宜；但同规格下算上每月免费分钟，要跑到 4,000 分钟以上成本才会反超。而且不能跑 Docker daemon，适合短、轻、可丢弃的私有 CI，不是通用平替。

### 4.3 技术长文与工具发布（Blog & Release 风格）

**核心结构**：痛点起手 → 核心原理与架构选型 → 极简核心代码 → 真实局限与思考。

- **拒绝兜圈子**：第一段交代「为什么做它」，直面市场上已有工具的缺陷。
- **展示取舍（Trade-offs）**：任何技术方案都有代价。说明你为了简洁、速度或安全放弃了什么（如“为了纯本地运行，放弃了服务端复杂的缓存机制”）。
- **极简代码**：只贴核心关键逻辑，不贴冗长样板代码，关键行添加解释“为什么这么写”的简注。

## 5. 快速交付检查清单（Pre-flight Checklist）

在交付文本或结束审校前，逐条快速自查：

- [ ] **动作**：是否存在「进行……的分析/探讨/测试」？→ 还原为纯动词。
- [ ] **主谓**：核心主体是否明确？是否滥用了被动语态？
- [ ] **AI 警示词**：是否存在「此外」、「至关重要」、「格局」、「标志着」？→ 删除或平替。
- [ ] **虚假句式**：是否存在「不仅……更是……」、「作为……的证明」？→ 改为直接陈述。
- [ ] **排版**：中英文之间是否保留了空格（盘古之白）？专有名词大小写是否准确？
- [ ] **标点与符号**：是否清除了非必要的装饰性 Emoji？是否消除了破折号滥用？
- [ ] **节奏**：是否有连续三句长度雷同？默读一遍是否自然顺畅？
- [ ] **态度与细节**：是否有具体的数字、事实或明确的观点？是否读起来像无菌公关稿？
